## 受入条件と対応

| 条件 | 対応 | 検証 |
| --- | --- | --- |
| 通常のコミット前に文書を検査し、不整合でコミットを中止できる | pre-commitへ `docs-check` を追加。`devenv shell -- npm run docs:check` の終了コードをそのまま返す | 正常時のフック成功、不正なYAMLフロントマターと索引漏れで終了コード1を確認 |
| Markdown以外の変更でも参照切れを見逃さない | globやファイル種別の条件を付けず、作業ツリー全体を検査 | `lefthook.yml` だけをステージし、未追跡の検証用文書に対してpre-commitが失敗することを確認。検証用文書は削除済み |
| Node・npm・Lefthookはdevenvで実行する | 新ジョブのnpm実行もdevenvで包む | Node v24.21.0、devenv内のLefthook v2.1.15で確認 |
| 既存の整形・Lint・履歴操作の扱いを維持する | ステージ済みファイルの自動整形・報告用Lintを維持。merge/rebase/cherry-pick/revertのpre-commitスキップも維持 | 設定差分を確認。履歴操作のスキップは設定維持の確認のみで、実際の履歴操作は未検証 |

## 検証結果と残課題

- ステージが空の手動実行ではジョブが実行されないため、手動確認コマンドには `--force` を付ける。`devenv shell -- lefthook run --force --job docs-check pre-commit` が成功した。文書以外をステージした通常の `devenv shell -- lefthook run pre-commit` でも不正文書の検出を確認した。
- 最終検証はすべてdevenv内で実行：`npm run format`・`npm run lint`・`npm run format:check`・`npm run docs:check`（152文書・15機能）・`lefthook run pre-commit` が成功。`git diff --check` も成功した。既存テストの削除・skip・期待値変更はなし。検査ロジックやアプリ実行コードに変更がないため、アプリ全テスト・型検査・ビルドは今回再実行していない。
- 作業ツリーを検査するため、未ステージ・未追跡の文書も影響する。ステージ内容だけを隔離して検証する実装ではない。CIの検査も引き続き必要。フックの導入方法・適用範囲は[文書運用](../development/documentation.md)に記録した。
- アプリ実行コード・UI・生成指示・認証認可・承認版固定・停止契約は変更していない。実GCP・実モデル・本人/現場評価、音声入力、全受入条件の実装監査、外部OKFツールとの相互運用、独立レビューは前回から未解決のまま引き継ぐ。担当役割：AI・基盤・検証担当、個人未割当。
