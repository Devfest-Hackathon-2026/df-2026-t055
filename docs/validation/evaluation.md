# 評価基準との対応

各0〜3点、合計24点。得点は予告せず、設計と動作・比較結果を提出材料にする。

| 分野・評価項目 | この設計で対応する内容 | 提出に残す証拠／担当 |
| --- | --- | --- |
| Google技術：中核で有効に機能するか | 時間情報と声かけを含む手本をVertex AIで工程化し、Cloud Runで利用へつなぐ | 実ジョブID・モデルID・下書きと原動画時刻、写真比較の判定／AI・検証担当 |
| Google技術：採用理由が合理的・具体的か | [関連仕様](../architecture/decisions.md)の4方式比較、Cloud Runと保存分離の理由、推論の費用制御 | 比較表、修正負担、使用額／AI・基盤担当 |
| 完成度：操作が一連の流れとして動くか | 動画登録から承認、本人の固定表示、新人引き継ぎまで接続 | デプロイURL、結合チェック、操作録画／基盤・結合担当 |
| 完成度：対象ユーザーが目的を達成できるUI・UXか | 役割別画面、1工程1画面、本人が進行を選ぶ、常時の支援要求・停止 | 操作観察、迷った箇所と変更点、協力者の属性と実施条件／体験担当 |
| 完成度：安全性・拡張性・保守性を意識するか | 認可、下書き分離、承認スナップショット、版固定、型・状態遷移、通信断時停止 | 権限・競合・失敗時の検査結果、構成とAPI契約／API・基盤担当 |
| 社会課題：課題が具体的・明確か | 知的障害のある人の作業手順の個別化と、担当者間の教え方の引き継ぎに焦点を置く | 採択案・参考資料の出典、就労現場の作業実例、協力者からの聞き取り記録／検証担当 |
| 社会課題：機能・仕組みが課題解決に有効か | 同一作業で作成負担、工程抜け、新人への伝わり方、支援要求を比較し、棄却条件で判断 | 計測値、動画必要性の判定、実利用評価とチーム内操作確認の区別／検証・提出担当 |
| ピッチ：デモと構成が明快でインパクトがあるか | 課題→手本の時間情報→AI下書き→人の判断→本人と新人の利用→結果を一つの作業で示す | 動く画面の録画、比較結果、AI利用と学びを含む提出説明／検証・提出担当 |
