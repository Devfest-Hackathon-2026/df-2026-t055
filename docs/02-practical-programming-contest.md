# 実際のアプリケーション開発に近い競プロ

- 投稿: markun46490:10
- 状態: 対話をもとに具体化した構想。課題の根拠、実現方法、効果は未検証。

## 1. 元の案

- 競プロや既存のコーディングテストは、実際のアプリケーション開発に直接つながるような問題をとくことはなく、アルゴリズムをひたすらやるのがおもしろくない。ISUCONやCTFのような実務との関わりが近い形式での問題を解くものがほしい。

## 2. Why：誰の、どんな課題か

- カテゴリ候補: 教育。
- アルゴリズムの力はビジネスロジックにも役立つ一方、アプリ開発ではデータベース、N+1などのクエリ、メモリ管理、フロントエンドのフェッチのタイミング、アクセシビリティ、データ保持など、別の知識や判断も求められる。
- 既存のアプリを読み解き、実際の開発に近い課題に取り組みながら、アプリケーション開発を学べる場を目指す。
- 実践機会が不足しているという課題や既存教材との差は仮説。対象者へのヒアリングや既存サービスの調査は未実施。

## 3. What：問題と参加体験

1. 参加者はブラウザ上の、ファイルの検索・編集やターミナル操作ができる開発環境を開く。
2. 実際のアプリに近いコードベースと、達成条件を明記したチケットを受け取る。
3. 関連コードや仕様を読み解き、修正してテストを通す。AIの利用は任意。
4. 問題ごとのベンチマーカーを繰り返し実行し、結果を見ながら改善する。最終的な成果はスコアで示す。

- 問題例の候補: N+1などの性能改善、フロントエンドのフェッチ、アクセシビリティ改善。最初の題材や問題は未決定。
- 性能課題なら性能指標、アクセシビリティ課題ならその検査指標など、課題に合ったベンチマーカーを検討する。自動検査では測れない点もあるため、何を評価しているかを明示する。
- ECサイトやSNSなど複数のアプリを題材にし、問題を定期的に追加する構想。同じアプリに複数のチケットを用意し、コードベースへの理解を活かせるようにする。各チケットは独立した初期状態から開始し、前の修正を引き継がない。
- 個人の練習にも、企業の採用時のコーディングテストにも使えることを目指す。採用でスコアだけから技術力全体を判断できるとは限らない。

## 4. ハッカソンで示したい範囲

- 一つのアプリを対象に、ブラウザからチケットに取り組み、修正とベンチマークを実行し、結果を確認できるところをピッチの中心にする。問題や採点指標は未決定。
- 既存のコーディングエージェントを使いながら課題に取り組む体験も見せられるとよい。まずはGeminiを候補にするが、5日間で用意できるかは未確認。
- 複数アプリ・定期的な問題追加・企業による出題や成果共有は今後の発展として示す。
- ブラウザ開発環境、実行環境の隔離、安全な採点、コストと実装期間は未検証。具体的な構成を決める前に検討が必要。

## 5. AIと企業への共有

- AIの利用は任意。ベンチマークのスコアにAIとのやり取りは含めない。
- 既存のコーディングエージェントと連携し、プロンプトと回答の両方を記録できれば、企業が開発過程を知る参考になる。参加者が企業への共有を選んだ場合、一連の履歴をまとめて共有する構想。記録開始時と共有前に何が記録・共有されるかを示す必要がある。
- MCPや `AGENTS.md` のような指示ファイルに連携方法を記載する案が出たが、具体的な仕組みは未決定。指示ファイルやMCP接続だけで履歴が漏れなく記録される保証はなく、外部ツールでのやり取りも把握できない。
- 将来は企業が問題を作成・公開し、共有に同意した参加者の成果や履歴を見て人材と出会える可能性を検討する。企業向け機能は未実装。
