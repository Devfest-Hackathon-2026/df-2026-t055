# 本人の選択・拒否・伝え直しを支える

- 投稿: 壁打ちで具体化した案
- 状態: 保留・未検証
- 更新: 第1回蠱毒（予選C）の指摘を反映。実績や効果は未検証のまま。

## 1. 元の案

その場で選べる活動などを本人に分かる写真・短文で提示し、選ぶ・断る・別の希望を伝えることを支援する。

## 2. Why：誰の、どんな課題か

- カテゴリ候補: 医療・福祉。
- 対象・課題の仮説: 口頭の質問だけでは希望を表しにくい本人。
- 根拠: [意思決定支援ガイドライン](https://www.mhlw.go.jp/stf/newpage_76171.html)は本人に合った情報提供・意思表明を重視する。想定画面が本人に合うかは未確認。
- 意図: 職員の理解だけでなく、本人が意思を表せる機会を増やす。口頭だけでなく、選ぶ・断る・「どれでもない」・「やめる」を同じ場で使えるようにする。

## 3. What：解決策と最小の体験

- 操作案: 職員が今日の活動と写真を登録する → Geminiが写真付き短文の候補を下書きする → 職員が確認して採否を決め、承認後の表示を固定する → 本人が選ぶ・断る・保留・「どれでもない」・「やめる」 → 職員が受け取り対応する。
- MVP候補: 1場面の実際の選択肢と、「どれでもない」「やめる」。承認した表示はその場では作り直さない。
- 強みとして残す点: 「どれでもない」と「やめる」を最初から置くこと、職員承認後は表示を固定して本人に見せること。
- 対象外: 押した内容だけで本人の理解や意思の確定を判定する機能。本人の意思をAIが推測して選ばせる機能。
- 誘導リスク: 職員やAIが用意した選択肢へ本人を誘導する危険がある。対策案は、(1) 用意した候補以外を「どれでもない」で返せる、(2) 「やめる」で中断できる、(3) 下書きの採否は職員が決める、(4) 押し操作だけでは意思確定と見なさない。対策の効果は未検証。

## 4. How：Google技術と候補比較

- 候補: Geminiで、職員が登録した活動と写真から「写真＋短文」の表示候補を下書きする。実行はCloud Run。必要なら共有状態をGoogleのデータ基盤で管理。未採用・未実装。
- 固定画面との比較（仮説）: 同じ活動が毎日繰り返され、紙の絵カードや既存AACの固定画面で足りるなら、Geminiは不要。比較対象は実物・紙の絵カード、既存AAC、[Proloquo](https://www.assistiveware.com/products/proloquo)、[Volition](https://www.myvolition.org/)。
- Geminiが必要になり得るのは、その日の活動が日によって変わり、毎回の短文・写真付き選択肢の準備が職員の負担になる場合、という仮説。手書きでも下書きは作れるが、毎日変わる候補をその場で揃える作業を減らすのが狙い（効果は仮説）。
- 本人が見る画面は、承認後に固定する。生成のたびに表示が変わると使いにくくなる、という資料上のデメリットへの対応。固定した画面は、同じ活動が再出したら再利用する。
- メリットの仮説: その日の表示準備を減らせる。写真と短文をまとめて下書きできる。
- デメリット: 不適切な選択肢による誘導、表示変更による使いにくさ、職員の確認負担。毎回生成すると慣れを妨げる可能性。
- 検証: 同じ1場面で、(a) 職員が手で短文を書く、(b) Gemini下書き＋職員確認＋固定、(c) 既存の固定画面（絵カード／AAC）の再利用、の準備時間と、本人が選ぶ・断る・「どれでもない」・「やめる」を行えるかを比べる。所要時間の実測値はまだない。
- 棄却条件: (c) が実際の場面で (b) 以上に足りる、既存AAC等との差を示せない、承認後も表示が安定しない、用意した選択肢への誘導が減らない、のいずれかに当たれば、Geminiの役割を外すか、案自体を見送る。

## 5. AIをどこで、なぜ使うか

職員向けの、その日の「写真＋短文」表示下書きに使う案。本人の意思を推測して選ばせない。本人対面中に表示を再生成しない。採否と固定は職員が決める。文書整理・調査でのAI利用は[共通記録](intellectual-disability-welfare-review.md#ai利用と判断)を参照。

## 6. 検証・完成度・デモ

- 5日間（11/5 10:00〜11/10 19:00）のデモ案: 職員が今日の活動と写真を登録する → Geminiが写真＋短文の候補を下書きする → 職員が直して承認し、表示を固定する → 本人（または本人不在時は職員役と明記した代役）が「選ぶ・断る・保留・どれでもない・やめる」を押す → 結果が職員側に届き、対応できる、までをCloud Run上の1場面で通す。
- これは操作の通し確認であり、フロー案で終わらせないための最小デモである。未実装。
- 職員役だけのデモでは、本人に使いやすいとは主張しない。対象ユーザーのUI・UXは、本人と一緒に同じ場面を試すまで評価しない。
- 検証すること: (1) 本人が選択・拒否・「どれでもない」・「やめる」・やり直しを自分で行えるか、(2) それが職員に届いて対応につながるか、(3) 固定画面（絵カード／AAC）と比べて準備または意思表明のしやすさに差があるか。
- 本人と試す機会が取れない場合は、核心の価値を評価できない。そのときは案を確定せず、再検討条件を満たすまで提出案にしない。
