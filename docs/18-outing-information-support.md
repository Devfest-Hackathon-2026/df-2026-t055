# 外出前に参加条件と不明点を整理する

- 投稿: 2回目の調査で具体化した案
- 状態: 比較実験の候補。福祉アプリとしての採用は保留で、17より優先度を下げる。

## 1. 元の案

本人が関心を持った催しについて、支援者が公式案内やチラシから参加条件を調べ、不明点を問い合わせる前の整理を助ける。

## 2. Why：誰の、どんな課題か

- カテゴリ候補: 医療・福祉／観光。採用時に主カテゴリを決める。
- 対象・課題の仮説: 本人の外出希望を受け、料金・予約・付き添い・休憩・途中退出などを複数資料から探す本人と支援者。
- 根拠: [意思決定支援ガイドライン](https://www.mhlw.go.jp/stf/newpage_76171.html)は本人の希望の実現に向けた支援を重視する。情報整理の手間や、このアプリへの需要は未確認。
- 既存の実践: [日本科学未来館](https://www.miraikan.jst.go.jp/aboutus/accessibility/)は「あんしんガイド」「あんしんマップ」などを提供している。こうした資料の存在は、追加アプリが必要という根拠にはならない。

## 3. What：解決策と最小の体験

- 操作案: 一つの催しの公式URLやチラシを渡す→必要条件を原文と並べる→不明・資料間の相違を確認→必要なら会場へ問い合わせる。
- 最小構成の候補: 既存資料の取込、条件・原文・不明点の表示。
- 対象外: 本人に合う会場の自動判定、写真や配慮の創作、本人向け説明の自動公開。
- 新規の本人プロフィールや日々の記録は要求しないが、資料探索・取込・確認の仕事は残る。

## 4. How：Google技術と候補比較

- 候補: GeminiをVertex AI経由で使い、画像・表・本文の条件を整理。Cloud Runで実行。未採用・未実装。
- 技術の根拠: [Geminiの文書理解](https://ai.google.dev/gemini-api/docs/document-processing)。画面や資料の読取と、現地の状況確認は別である。
- メリットの仮説: 複数資料から同じ確認項目を探す負担を減らせる。
- デメリット: 情報が未公開なら解決できない。日時・対象イベントの取り違えや訂正負担もある。
- 比較対象: 公式ガイドをそのまま読む、紙やメモのチェックリスト、同じ資料と指示を渡した汎用Gemini。

## 5. AIをどこで、なぜ使うか

資料に書かれた条件を取り出す部分に使う案。書かれていない配慮を推測しない。本人の参加可否を決めず、分からないことを問い合わせる判断は人が行う。

## 6. 検証・完成度・デモ

- 公開資料を使い、探索・取込・原文確認・訂正までの時間と、重要条件の誤り・創作を比較する。
- 詳しい既存ガイドがある例と、情報が少ない例を両方含める。問い合わせの準備や回答待ちも省略しない。
- 開発者だけで試す場合は、開発者内の作業比較と記載する。実際の支援者の時短や、本人の理解・外出機会の増加は主張しない。
- 原文と対象日時を確認し、情報が古い場合や取込に失敗した場合は明示する。

## 7. 未決定事項・次の確認・学び

### 採用を保留する理由

- 十分な公式ガイドがある会場では、本人と一緒に既存資料を読む方が早い可能性がある。
- 情報が少ない会場ではAIでも分からず、問い合わせが必要になる。
- 情報抽出の時短、本人の理解、参加機会の増加は別々に確かめる必要がある。
- 本人向け説明の生成と適合判定を外すと、一般的な情報探索の補助になり、福祉専用アプリとして作る理由が弱くなる。

棄却条件: 公式資料や汎用AIより準備・確認が減らない、不明情報が多く次の行動が変わらない、訂正負担が利益を上回る場合。開発による学びは未記入。
