## 1. 元の案

- 同い年の死亡例を毎日体験するアプリ

## 2. Why：誰の、どんな課題か

- カテゴリ: 教育。死を自分ごととして捉え、生活や価値観を振り返る体験は、治療や福祉サービスではなく学習の場だと判断した。提出時の公式資料への適合文言は未確認。
- 対象ユーザー: 同年代の死を自分から遠いことと感じ、生活や価値観を振り返るきっかけを日常で得にくい人。
- 利用目的: 出典付きの同年齢帯の死亡に関する事例を、本人の意思で閲覧し、振り返りの問いとともに読むことで、死を自分ごととして捉え直し、生活や価値観を見直すきっかけを得る。
- 解決したい社会課題（仮説）: 同年代の死が「自分には起きないこと」として日常から切り離され、生活や価値観を見直すきっかけが得にくい。
- 根拠: 未確認。対象者がこの課題を自分のこととして認めるか、利用したい理由と避けたい体験をヒアリングする。利用できる統計や事例の出典・利用条件も調べる。
- 人間が決める意図: 刺激の強さや毎日の利用を目的化しない。体験は任意で、いつでも中断できる。本人が得るのは、死を自分ごととして捉え直し、生活や価値観を見直すきっかけである。プロダクト名に「毎日体験」とあっても、毎日の強制利用は目的にしない。
- 検証方法（仮説の確かめ方）: 先に利用目的の説明への反応と懸念を聞く。閲覧テストは参加意思を確認したうえで行い、同年代の死を自分ごととして捉え生活や価値観を振り返れたか（価値）と、心理的負担の両方を調べる。
- 棄却条件: 次のいずれかに当てはまる場合は、案を捨てるか根本から作り直す。(1) 利用条件を満たす出典付きデータを用意できない。(2) 対象者がこの課題を自分のことと認めない。(3) 心理的負担が振り返りの価値を上回る。(4) 閲覧前の説明と中断・非表示を十分に提供できない。

## 3. What：解決策と最小の体験

- 解決の仕組み（仮説）: 出典を示せる同年齢帯の事例を、生活や価値観を振り返る問いとともに、本人の意思で読む。記事や統計を読むだけより振り返りに寄与するかは未検証。
- 操作フロー:
  1. 閲覧前の説明を読む（利用目的、見る内容、出典を示すこと、いつでも中断・非表示できること）。
  2. 閲覧するか選ぶ。
  3. 出典付きの同年齢帯の事例と振り返りの問いを見る。
  4. いつでも終了・中断・非表示できる。
- MVP: 許諾・出典を確認できる少数の事例、閲覧前の説明、中断・非表示、振り返りの問い。個人を特定できない、公開利用できる事例や、利用条件を確認した公開の年齢階層の情報を優先する。個人が特定される死亡事例は、許諾があっても MVP の対象外で後の拡張とする。許諾・出典のない個人事例は使わない。
- 今回の対象外: 強制的な毎日の通知、刺激的な再現、個人の死亡リスクや余命の推定。
- 既存の手段との差（仮説）: 記事や統計を読む行為より振り返りに役立つか、負担が増えないかを確認する。

## 4. How：Google技術と候補比較

Firestore を事例データの中核管理に採用し、Firebase Hosting を指定実行基盤に採用する。未実装。

| 候補 | 判定 | 役割・採用理由 | メリット | デメリット・要確認 |
| --- | --- | --- | --- | --- |
| Firestore | 採用 | 確認済みの事例を、出典・利用条件・公開/取り下げ状態と対応付ける中核データ管理。出典管理と問題のある事例の取り下げがこの案の中核であるため。 | 事例と出典を対応付ける構成に向く | 公開範囲、利用条件、更新・削除の設計 |
| Firebase Hosting | 採用 | 事例閲覧画面の指定実行基盤。少数の事例から閲覧体験を確認できる小さな画面に合う。 | 少数の事例から体験を確認できる | データの閲覧権限と更新方法は別途設計 |
| Cloud Run | 不採用（MVP） | 事例取得・加工の実行基盤として比較した。小さな閲覧機能には過剰と判断した。サーバー側の取得・加工が必要になったら再比較する。 | 取得・加工の制御をまとめられる | 小さな閲覧機能に対して現時点では不要 |

- 採用技術と選定理由: Firestore は事例・出典・利用条件・公開可否の対応付けという中核処理を担う。Firebase Hosting は必須の指定実行基盤として閲覧 UI を提供する。付け足しではなく、出典付き事例を安全に見せる構成の中核とする。
- 採用しなかった案と理由: Cloud Run は MVP の小さな閲覧機能には不要。死亡例を生成AIに作らせる案は、正確性の観点から採用しない。死亡例の創作はしない。

## 5. AIをどこで、なぜ使うか

- プロダクト内の利用: Gemini は振り返りの問いを下書きするためだけに使う。実在する死亡例を創作させない。固定の問いで足りる場合は、プロダクト内で Gemini を使わない。
- その場面で使う理由: 固定の問いで不足するかを確認する。個別生成が必要でなければ利用しない。
- 人間が判断・確認すること: 事例の選定、出典と許可、問いの表現、閲覧頻度、利用を止められる体験。
- 開発支援の利用実績: 文書整理は[共通記録](../README.md#この文書でのai利用)を参照。以降の利用は場面・理由・人間の判断を追記する。
