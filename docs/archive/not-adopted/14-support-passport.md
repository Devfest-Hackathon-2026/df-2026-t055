# 場所や担当が変わっても使える支援パスポート

- 採択案: [11A 本人に合わせた作業手順の提示](../adopted/11-personalized-task-guidance.md)
- 検討時の状態: 保留・未検証

## 1. 元の案

通所先の変更、短期入所、入院などで担当が変わるとき、本人の伝え方・好み・必要な配慮を引き継ぎ、何度も一から説明する負担を減らす。

## 2. Why：誰の、どんな課題か

- カテゴリ候補: 医療・福祉。
- 対象・課題の仮説: 初めての相手に本人に合う関わり方を伝える本人・家族・支援者。
- 根拠: [NHSの支援パスポート](https://www.nhs.uk/conditions/learning-disabilities/going-into-hospital/)に同種の情報共有の実践がある。対象現場での不足は未確認。
- 意図: 本人に関する情報を、必要な相手と必要な場面へ引き継ぐ。
- 既存との関係: 支援パスポート自体は既存の取り組みである。この案の差は、新しい種類のパスポートを作ることではなく、項目ごとに情報源・確認日・共有範囲を残し、送り手が場面別に渡せるものと、受け手がその場面で必要な項目だけを見られる流れを同じ画面で通すことにある（仮説。検証は6章）。

## 3. What：解決策と最小の体験

本線は送り手と受け手の両方である。

1. 送り手: 既存資料から、ある引き継ぎ場面向けの項目を下書きする。各項目に情報源、確認日、共有範囲を付ける。
2. 本人・支援者が内容と共有先を確認する。AIは本人像や好みを確定しない。
3. 受け手: その場面で共有された項目だけを見る。
4. 必要なら更新する。更新した人と確認日を残す。送り手は共有を取り下げられる。

- MVP候補: 1つの引き継ぎ場面、少数の確認済み項目、項目ごとの情報源・確認日・共有範囲。画面に共有の取り下げと更新者の記録を入れる（設計案。未実装）。
- 対象外: 全機関の記録連携、本人像の自動確定、古い情報の無条件な再利用、参加可否などの判定。
- 運用について: 施設をまたぐ共有・更新の運用は、アプリを作るだけでは決まらない。そのため全機関の連携は扱わず、1つの引き継ぎ場面に限って「誰が共有するか・誰が取り下げられるか・誰が更新するか」を画面上の記録として置く。これでも受け入れ先が実際に読むかは未検証である。

## 4. How：Google技術と候補比較

- 候補: Geminiは既存資料から場面別の項目を抜き、各項目に情報源・確認日・共有範囲の欄を付けた下書きを出す。実行基盤の候補は Cloud Run。保存と共有制御（共有範囲、取り下げ、更新者）は要設計。未採用・未実装。
- Geminiを中核に置く理由（仮説）: 紙の定型欄やキーワード検索では、資料のどこに何が書いてあるかを場面ごとに切り出し、情報源を項目に結びつける作業が残りやすい。汎用の要約は出典や確認日を落としたり、資料にない解釈を足したりし得る。この案では、抜き出しと出典の対応付けをGeminiが下書きし、確定は人が行う。資料整理の要約だけを目的にはしない。
- メリットの仮説: 既存資料から、その場面で必要な項目を情報源つきで抜き出せる。受け手は共有範囲内の項目だけを見られる。
- デメリット: 必要な情報の抜け、古い解釈の固定、共有・更新管理、受け手が読まない可能性、作成・最新化の負担増。
- 比較対象: 紙の支援パスポート、既存の引き継ぎ、[Volition](https://www.myvolition.org/)、汎用AIによる資料整理。

## 5. AIをどこで、なぜ使うか

Geminiは、既存資料から場面別項目を抜き、情報源・確認日・共有範囲の欄を付けた下書きを作るところに使う。本人が何を好むか、どの相手に渡すべきかをAIが確定しない。確認と共有先の決定は本人・支援者が行う。文書整理・調査でのAI利用は[共通記録](../intellectual-disability-welfare-review.md#ai利用と判断)を参照。

## 6. 検証・完成度・デモ

検証の本線は、送り手の準備と受け手の確認の両方である。

- 比較対象: （a）紙の支援パスポート、（b）汎用Geminiによる資料整理、（c）この流れ。
- 見るもの（仮説の検証指標）: 受け手が必要な項目を見つけるまでの時間、抜けた項目や誤った項目の数。送り手の準備時間も記録する。
- 範囲: 1つの引き継ぎ場面に限る。
- 5日間のデモ: 架空資料を使い、Cloud Run上で「下書き→確認→受け手の閲覧→更新・取り下げ」まで通す。架空資料での表示確認は、本人の安心や支援効果の実証ではない。受け手が実際に読むかも、このデモでは示せない。
- 安全性の材料（設計）: 共有範囲、取り下げ、更新者、確認日を項目ごとに画面へ出す。

棄却条件:
- 紙の支援パスポートや汎用Geminiと比べて、抜け・誤り、または受け手が項目を探す時間が減らない場合は、この案を捨てる。
- 共有した相手が実際に読まない、使わない場合は、この案を捨てる。
- 作成・最新化の負担が、紙や既存の連絡を上回る場合は、この案を捨てる。
