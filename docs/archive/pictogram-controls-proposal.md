# 本人向けの操作をピクトグラムで伝える

提案日：2026年11月7日。

対象は[設計フリーズ v0.1](design-freeze-2026-11-07.md)の本人向け画面。文字を読まずに操作の目的を確かめられるよう、ボタンに絵やマークを添える。

## 表示する操作とマーク

「手伝って」「やめる」を優先し、「はじめる」「もどる」「つぎへ」「つづける」「おわる」や、読み上げを使う場合の再生ボタンにも同じ方針を適用する。絵やマークは大きく表示し、短い文字ラベルを添える。

| 操作 | 検討する絵やマークの例 | 押した後の動作 |
| --- | --- | --- |
| 手伝って | 人に助けを求める様子、職員を呼ぶ絵 | 進行を止め、支援を求める |
| やめる | 止まることを表すマーク | 確認ダイアログを挟まず直ちに作業表示を閉じる |
| もどる・つぎへ | それぞれの向きを示す矢印 | 本人の操作で工程を移る |
| はじめる・つづける・おわる | 開始・再開・完了をそれぞれ表す絵 | 既存の開始・再開・完了操作を実行する |

この表は選定時の例とする。職員が実際のボタンと結果を本人に示し、意味を確かめてから使う。同じマークは同じ意味に使い、すべての本人画面で形・配置をそろえる。特に「手伝って」と「やめる」は見分けられる絵にする。

## 支援待ち・停止・通信失敗の表示

押した後も、文字と絵を組み合わせて状況を伝える。

- 支援要求の送信成功後は、職員を呼んで待つ様子を表示する。送信中と職員へ届いた状態は区別する。
- 作業をやめたときは、止まった状態を表す絵を表示する。停止状態は通信断・再読み込み後も保つ。
- 支援要求を送れないときは、近くの職員に直接声をかける・合図する様子を表示し、「近くの職員をよんでください」と案内する。

「手伝って」「やめる」は常に同じ位置から押せるようにする。絵を表示するための読み込みや音声再生を待たず、既存の支援要求と即時停止が動くようにする。

## 見え方と操作性

- 色に加えて絵・形・配置で操作を区別する。絵の細部が見え、大きくしても意味を確かめられるようにする。
- ピクトグラムの画像資産を固定し、表示する端末間で見え方を確認する。絵文字を使う場合も、採用する表示を職員と本人が確認する。
- キーボード操作とフォーカス表示を保つ。ボタンには支援技術が読み取れる名前を付け、絵と文字が重複して読み上げられないようにする。
- 使用する絵の出典・ライセンスを記録する。

なじみのある絵を関連する内容に添える方針は[W3Cのアイコンに関する認知アクセシビリティの解説](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o1p07-icons-used/)を、色以外でも意味を伝える方針は[W3CのUse of Colorの解説](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)を参考にする。

## 確認すること

本人の希望を確かめながら、文字を読まずに「手伝って」と「やめる」を選び分けられるか、押した後の状態が分かるかを確認する。意味が伝わらない場合は職員が直接説明し、絵や提示方法を見直す。

小さな画面、拡大表示、色の見え方が異なる場合、キーボード・スクリーンリーダー、通信断を含めて確認する。理解の確認と、支援要求・再開・停止・完了が既存どおり動くことを別々に確かめる。
