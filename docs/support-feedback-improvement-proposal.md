# 設計変更候補：支援中のつまずきを記録し、後から手順を改善する

提案日：2026年11月7日。

対象は[設計フリーズ v0.1](design-freeze-2026-11-07.md)の支援対応と手順の更新。支援の記録を次回の手順作成にも使う。関連する追加候補は[職員の音声によるAI修正依頼（PR #7）](https://github.com/Devfest-Hackathon-2026/df-2026-t055/pull/7)に記載する。

## 目的と既存設計との差分

本人が作業中につまずいたときは、職員がその場で支援し、表示中の手順で作業を続ける。つまずきと支援内容は蓄積し、職員が後から更新を指示したときに、AIが改善した手順の下書きを作る。本人が生成を待つ時間を避け、支援の経験を次回へ引き継ぐことを目指す。

既存設計には「手伝って」、職員による対応済みの記録、本人の「つづける」、実行中の手順の版固定がある。追加する候補は、職員の対応開始、テキスト・音声による支援記録、本人別の手順一覧、蓄積した記録を使う更新操作である。

## 支援中の流れ

1. 本人が「手伝って」を押す。進行を止め、職員の支援一覧に対象者・作業・工程を表示する。
2. 到着した職員が、自分の認証済み支援画面で「対応を始める」を押す。到着・対応開始を記録し、入力用のモーダルを開く。
3. モーダルには「どこでつまずきましたか」「どのように支援しましたか」「次回の説明で変えたいこと」を用意する。テキストまたは音声で入力し、音声は文字起こしを確認・訂正してから保存する。実際に見たことと、職員の改善提案を分けて残す。
4. 職員はその場で本人を支援する。入力は支援後にも行え、「後で記録する」でモーダルを閉じられる。記録の完了やAIの応答を、支援・作業再開の条件にしない。
5. 支援を終えた職員が「対応完了」にする。到着・対応開始と対応完了は別に記録する。
6. 本人が「つづける」で同じ工程へ戻り、できたら「つぎへ」を押す。その回は開始時の手順を使い続ける。再度「手伝って」を押した場合は、別の支援対応として記録を追加する。

職員の入力欄は職員の認証範囲に置く。本人の画面では、既存の支援要求・再開・停止の操作を使う。

## Aさんの作業手順一覧から更新する

職員向けに、本人を選んで作業手順を確認する一覧を用意する。各カードには作業名、次回使う承認済みの手順、未反映の記録件数、更新状態、「記録をもとに更新」ボタンを表示する。例として「チラシを封筒に入れる」「お菓子を箱に詰める」を並べる。

1. 職員がカードから記録を確認し、改善に使う内容を選んで「記録をもとに更新」を押す。
2. AIは現在の承認済み手順、選択した記録、職員が確認した本人共通の説明方法をもとに、新しい下書きを非同期で作る。元動画の再解析が必要かは変更内容から判断し、記録を追加するたびに全動画を再解析する方式は前提にしない。
3. カードは「生成中」、生成成功後は「職員の確認待ち」と表示する。職員は変更前後、使用した記録、必要な原動画の区間を照合し、写真・説明を編集して承認する。
4. 承認後、職員が新版を次回使う手順に指定する。実行中の本人セッションは開始時の版を使い続ける。
5. 生成に失敗した場合も、現在の承認済み手順と支援記録を保持し、職員が再試行できるようにする。

生成に使用する手順と記録は、更新を開始した時点で固定する。生成中に増えた記録は次の更新候補として残す。各記録について、どの下書きで参照し、どの承認版で変更を採用したかを追えるようにする。「生成成功」と「手順への反映」は分け、未採用の指摘も残す。

## 記録の範囲と今後作る手順への利用

支援記録には、本人、作業、使用中の承認版、工程、セッション、支援要求、記録した職員と日時をひも付ける。同じ本人でも作業固有の指摘は、その作業の更新に使う。

「折る工程を二つに分けたら進められた」といった個別の経験から、他の作業にも使う説明方法を職員が確認して選び、本人共通の情報として保存する。今後別の作業手順を作るときは、その時点で職員が確認した本人共通の情報を入力に含める。本人の希望を確認し、共通情報も見直せるようにする。

## 採用前に確かめること

- 支援中・支援後の入力負担、音声の訂正負担、記録の残し忘れを確認する。
- 手順と記録からの修正で足りる場面と、元動画の再解析・写真の切り出しが必要な場面を比較する。
- 生成時間に加え、記録・修正・確認・承認を含む職員の総作業時間を測る。
- 同じ工程で複数回支援を求めた場合、生成中に記録が増えた場合、生成失敗、新版承認後も作業中の表示が変わらないことを確認する。

採用時には、フロント・API・AI担当が、対応開始と完了の状態、支援記録の保存と権限、生成への入力、参照・採用した記録の管理を設計へ反映する。音声入力の方式、音声データの送信先・保存方針・費用も決める。
