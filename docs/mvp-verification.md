APIテストはHTTPと共通のFetchルーターを直接呼び、認証・Origin・スキーマ・承認・メディア配信・イベントを検査した。インメモリ保存だけでなく、全I/OをPromiseで返すRepositoryアダプタでもフローを検証した。トランザクションの並行更新・承認・開始とロールバックも検査した。

動画検証はffmpegで生成したテストパターン＋音声のMP4を使う。ffprobeによる形式・音声・時間検査、ffmpegによるJPEG切り出し、承認時の版専用コピーまで実行した。これは実作業の手本ではなく、作業の説明の正しさや使いやすさの評価はしていない。

ブラウザ側で使用する送信待ち処理をテストし、停止状態を送信前に保存すること、通信断後に再送できること、送信成功後も停止を解除しないことを確認した。nextとhelpの競合は同じイベントIDで最新revisionへ合わせて再送する。重複helpによって再開不能にならないことも確認した。

環境：Node.js 24.22.1、ffmpeg / ffprobe 8.1.2。ネットワーク制限のため利用可能なローカル依存を検証に使用（React / React DOM 19.2.5、Zod 4.4.3、TypeScript 5.6.3）。これらのコピーはnode_modulesにのみ置き、成果物には含めない。オンライン環境で `npm install` → `npm run build` とブラウザ操作を追加確認する。

Git管理領域が読み取り専用のため、5フェーズのコミットは別の書込可能なローカルGit領域で作成し、`mvp-phases.bundle` に保存する。元のGit HEADは変更していない。bundleは元HEADを前提とする5コミットだけを含み、依存や動画・画像・ログ・既存の未追跡プロンプトファイルを含めない。
