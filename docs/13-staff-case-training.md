# ベテランの経験から新人が練習する

- 投稿: 壁打ちで具体化した案
- 状態: 保留・未検証
- 更新: 第1回蠱毒（予選C）の指摘を反映。事実の追加はしていない。

## 1. 元の案

職員が経験した場面と判断の根拠をケース教材にして、新人が何を観察し、本人にどう確かめるかを練習できるようにする。

## 2. Why：誰の、どんな課題か

- カテゴリ候補: 医療・福祉／教育。採用時に主カテゴリを決める。
- 対象・課題の仮説: 関わりが浅い職員が、経験者の判断過程を学ぶ機会を得にくい。
- 根拠: 研修で困っている具体的な場面・頻度・現行教材は未確認。デモを「現場の必要性の証拠」としては扱わない。
- 意図: 経験を読み物にするだけでなく、確認の仕方を練習できるようにする。
- 検証計画（仮説）: デモの前に、経験者が何を観察し本人にどう確かめたかを、関わりの浅い職員が学びにくい具体的な場面があるかを確認する。
- 棄却条件: そのような不足が見つからない場合、または現行教材がすでにその確認手順を十分に教えている場合は、この案を捨てる。

## 3. What：解決策と最小の体験

- 操作案: 経験者が事例を説明→AIが教材を下書き→職員が確認→新人が対応を考える→根拠と別の可能性を振り返る。
- MVP候補: 職員がその場で確認した1ケースと、その場面で確かめるべきこと。1ケースは5日間で一連の操作を見せるための内容であり、成功の指標ではない。
- 正解の扱い: 職員が確認した根拠だけを正解とする。確認済みの根拠を外れたAIの解説は正解にしない。新人には一つの正解だけでなく、別の可能性も振り返らせる。
- 対象外: 本人の内面を再現したと主張するシミュレーター、一つの対応を万人の正解として採点する機能。

## 4. How：Google技術と候補比較

- 候補: Geminiで聞き取り整理・教材下書き・対話、Cloud Runで実行。未採用・未実装。効果は未検証。
- メリットの仮説: 経験を質問形式に整理できる。
- 汎用AIとの差（仮説）: 職員確認済みの根拠だけを正解にし、未見ケースで確かめるべき点を挙げさせる点。資料自身が「汎用AIのケース作成・ロールプレイとの違いが弱い」と認めてきた弱点への改良である。
- デメリット: 教材の創作や誤った一般化、監修負担。UIは対象ユーザー（関わりの浅い職員）による操作確認が未実施。
- 比較対象: 通常のOJT、既存の研修、汎用AIのロールプレイ。[MyCareAudit](https://mycareaudit.co.uk/ai-trust)にも事例の教材化・練習に関する説明がある。
- 監修負担の仮説: 1ケースの説明と職員確認は、教材を一から作る負担や、制約のない汎用AI出力を監修する負担より軽い。
- 検証計画: 説明・確認・更新にかかった準備時間を、既存教材の準備と汎用AIロールプレイの監修と比べる。
- 棄却条件: 監修・準備が既存手法より軽くならない場合、または経験者の説明・監修という新しい仕事が学習上の利点を上回る場合は、この案を捨てる。

## 5. AIをどこで、なぜ使うか

教材の下書きと、新人との対話練習に使う。確認済みの根拠を外れた解説を正解にしない。文書整理・調査でのAI利用は[共通記録](intellectual-disability-welfare-review.md#ai利用と判断)を参照。

## 6. 検証・完成度・デモ

- 本線の検証: 新人役に未見のケースを試してもらい、職員が確認した「確かめるべき点」を挙げられるかを、汎用AIのロールプレイおよび通常のOJTと比べる。この差は仮説である。
- 棄却条件: 未見ケースでの確認点の列挙が、汎用AIのロールプレイより優位を示せない場合は、この案を捨てる。数値の閾値は設けない。
- 使わない指標: クイズ正答率だけで現場の支援が改善したとは言わない。クイズ形式を使う場合でも、練習ループが回ったかの副次的な確認に限り、支援改善の証明にはしない。
- 5日間のデモ: 確認済みの1ケースで、聞き取り→下書き→職員確認→新人が考える→根拠と別の可能性の振り返り、までを通す。デモの成功は操作が一連で動くことの確認であり、課題が解けたことの証明ではない。
- UIの仮説: 関わりの浅い職員が、上記の一連操作を設計者の追加説明なしに完了できる。
- UIの検証: 新人役にそのループを実際に試してもらい、詰まる箇所を記録する。
- UIの棄却条件: 対象ユーザーが「何を観察し、本人にどう確かめるかを練習する」目的を達成できない場合は、UIを作り直すか案を捨てる。
- 実例を使う場合の扱いと教材更新も要検討。

### 再検討条件と棄却条件

- 再検討条件: 具体的な研修の不足があること、未見ケースでの確認点の列挙が汎用AIロールプレイおよび通常のOJTより優位であること、既存教材より準備・監修の負担が減ること、対象ユーザーが一連操作を完了できること。
- 棄却条件: 研修の不足が見つからない（または現行教材で足りる）、未見ケース評価で汎用AIロールプレイより優位を示せない、監修・準備が既存手法より軽くならない、対象ユーザーが目的の操作を完了できない、のいずれかに当たる場合は案を捨てる。
