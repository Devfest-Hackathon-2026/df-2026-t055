# 技術選定と比較

11Aにある比較対象は「直接教える」「写真数枚を並べる」「汎用AI」「MagnusCards」。Cloud Runや保存先の製品別の比較相手は11Aに列挙されていないため、ここではこの4方式を比較軸にする。データ保存先は新たな設計判断としてFirestore＋Storageを採用する。

| 採用要素 | pros：採用する理由 | cons：負担・失敗への対処 | 11Aの方式との比較 |
| --- | --- | --- | --- |
| Gemini動画解析／Vertex AI | 動作順、持ち替え、間、声かけを時刻付きの下書きとして取り出せる。工程を手入力する出発点を作る | 工程の欠落・時刻ずれ・誤認、撮影と修正の手間、推論費用がある。原動画照合、写真差替え、承認を必須にする | 直接教える方法は即座に対応できるが説明を繰り返す。写真数枚は作成が軽いが時間情報が落ちる。汎用AIとの違いは原動画との照合・承認・固定版を一続きにする点。MagnusCardsとは個別の手本動画から下書きを作る体験を比較する |
| Cloud Run | UI/APIと動画処理をコンテナにまとめ、職員の承認を通すサーバー境界を実装できる。指定実行基盤の要件も満たす | IAM、ビルド、コールドスタート、キュー連携の実装が要る。サービスを2つに絞り、非同期ジョブで画面を待たせ続けない | 直接指導・写真だけなら独自サーバーの管理は省ける。汎用AIやMagnusCardsを使う方法と比べ、自前の承認・版固定を管理する負担を引き受ける |
| Firestore＋Cloud Storage | 承認と版の作成をトランザクション化し、大きい動画と小さいメタデータを分ける。本人別割当とイベントをIDで結ぶ | コレクション間の整合性、画像コピー失敗、読取費用、削除運用が要る。トランザクション、参照検査、ポーリング間隔、保管期限で扱う | 写真を直接並べる方法はデータ管理が軽い。汎用AIの会話履歴や既存カードサービスへ運用を寄せる代わりに、今回の承認版と本人別割当を自分たちで保持する |

MagnusCardsの機能差は比較担当（検証・提出担当）が11/8午後に[公式紹介](https://www.magnusmode.com/magnuscards/)を読み、カードによる支援と今回の操作の差を比較記録に書く。他サービスの承認機能の有無を推測して優位性を説明しない。
