# パーソナル観光提案アプリ

- 投稿: Koki🍙(ちよ)18:14

## 1. 元の案

- 最初はパーソナライズされたパンフレットを作成するアプリを想定。

  →パンフレットの良さをデジタルにうまく融合したい

- museやgrokbotのようなパーソナルAIエージェントの登場により、実現がやりやすいように思える。

  →ただパーソナルAIエージェントを使うのと差別化をさせないといけない

- 個人だけでなく集団で旅行に行く時はコンテキストを共有して、全員に最適化させたい。
- また現在地と予定を照合して動的に、空き時間の提案や、注意事項などを喚起する。

## 2. Why：誰の、どんな課題か

- カテゴリ候補: 観光
- 対象ユーザー・困る場面（仮説）: 希望の異なる同行者と旅行を計画し、現地でも予定や空き時間に応じて行き先を調整する人。
- 解決したい社会課題（仮説）: 旅行情報が分散し、全員の希望や時間の制約を踏まえた情報を得にくいこと。
- 根拠: 未確認。グループ旅行での合意形成や現地の予定変更について、実際に困った場面を聞き、出典・日付を追記する。
- 人間が決める意図: パンフレットのどの良さを残すか、全員の希望をどう扱うか、AI任せにしない選択の仕方を決める。

## 3. What：解決策と最小の体験

- 解決の仕組み（仮説）: 同行者の希望と予定を共有し、見渡せる観光パンフレットとして候補・理由・注意点を提示する。
- 操作フロー案: 各自の希望と予定を入れる→共有パンフレットを比較する→全員で候補を選ぶ→現在地・空き時間を更新して次の候補を見る。
- MVP候補: 1地域・1グループ、希望の共有、パンフレット表示、現在地と空き時間を手動更新した再提案。
- 今回の対象外候補: 予約・決済、全国対応、常時の位置追跡、自動で全日程を確定する機能。
- 既存の手段との差（仮説）: muse・grokbotなど元の投稿で挙がったサービスや一般的なAI相談と比べ、全員が見渡し比較できる表示・共有が役立つかを確認する。03の行き先マッチング案との違いも整理する。

## 5. AIをどこで、なぜ使うか

- プロダクト内の利用案: 複数人の希望の整理、パンフレットの説明、予定変更時の候補の再提案。
- その場面で使う理由: 希望の違いや状況の変化を読み取り、候補の比較に役立つ説明を作れるか検証する。
- 人間が判断・確認すること: 全員の希望の扱い、参照情報、提案の根拠、最終的な行き先。条件が両立しない場合は隠さず選び直せるようにする。
- 開発支援の利用実績: 文書整理は[共通記録](README.md#この文書でのai利用)を参照。以降の利用は場面・理由・人間の判断を追記する。
