# 目的・対象者・安全条件

**プロダクト名は「しごでき」とする。** ブラウザのページタイトルと、職員・本人・新人の各画面に表示するサービス名を統一する。

## コンセプトと解決する課題

**知的障害のある人が、自分に合う方法で作業手順を確認できるようにするマニュアル作成・共有サービス。** 作業の手本を撮影すると、Geminiが工程や声かけの候補を下書きし、担当者が原動画と照合して修正・承認する。本人には承認済みの作業マニュアルを示し、担当者間では確認済みの教え方・工夫を引き継ぐ。

解決したい課題は、本人に合う作業手順の作成と、教え方の属人化・引き継ぎ負担。**「単にAIがマニュアルを生成する」だけでなく、本人に合わせて人が確認し、信頼できる版を利用できること**を中核価値とする。職員の時短、支援の質の向上は検証前の仮説であり、成果として断定しない。

## ターゲットと導入先を分ける

- **プロダクトが向き合う人：** 知的障害のある作業者本人と、その手順の作成・調整・支援・引き継ぎを担当する人。
- **利用できる就労場面の例：** 就労継続支援A型、就労継続支援B型、一般企業等での障害者雇用。**これら3種を別プロダクトや排他的なターゲット群として定義しない。**
- **今回の対象外：** 就労移行支援の制度固有の支援フロー、求職活動・就職支援の管理。就労移行支援を「第4のターゲット」として広げない。
- 所属先や雇用形態だけで、本人の理解や必要な配慮が決まるわけではない。**A型だからこのUI、B型だからこのUI、企業雇用だからこのUIと自動で決めない。** 障害名から画面の難易度・工程数・説明方法を推定しない。
- 施設・企業は導入先の例であり、**導入先すべてで有効と実証されたわけではない**。デモの1作業で確かめたことと、将来の適用範囲は区別する。

## 利用者ロール・テナントの解釈

| 設計上のロール | 現場での呼び方の例 | 責務 |
| --- | --- | --- |
| `staff`（設計書中の「職員」） | 支援職員、マニュアル作成担当、指導担当者 | 本人プロフィール・手本の登録、下書きの照合・編集、承認、割当、支援対応と記録 |
| `learner`（「本人」） | 作業者本人 | 自分に割り当てられた承認版の手順を確認し、進行・支援要求・停止を選ぶ |
| `newcomer`（「新人」） | 新人職員、引き継ぎ先の担当者・同僚 | 承認済み手順と確認済みの教え方を参照する（下書き編集・承認は不可） |

- 既存の `orgId` は組織・テナントごとの分離に用いる。A型・B型・企業雇用は、必要なら導入組織の**説明用属性**として扱い、実装上の権限や本人UIの難易度を直接決めるキーにしない。
- 本人向けの説明量、工程の細かさ、写真・短文・音声の使い分けは、本人の希望・実際の作業・担当者が確認した方法に基づく。**施設種別で別UIを自動切替する機能はMVPで確定していない。** 要件を採用する場合は別途仕様変更をレビューする。
- APIの `staff / learner / newcomer`、画面パス、承認・認可契約はこの整理だけを理由に変更しない。表現の読み替えと機能の変更を混同しない。

## 根拠となる背景（出典付き、適用範囲に注意）

以下は採択時の調査から引き継いだ背景情報。障害福祉に関する集計を、企業雇用の全体にそのまま一般化しない。

## 調査で確認した背景

- **技術活用の普及には余地がある。** 令和8年版厚生労働白書では令和6年度調査をもとに、手順書や記録様式の工夫による情報共有・負担軽減に取り組む事業所が74.8％、ICT・見守り機器等による業務量削減に取り組む事業所が38.0％と示されている。障害福祉で業務改善は進んでいる一方、技術を使った取組の普及には差がある。[白書・本文102〜103ページ](https://www.mhlw.go.jp/wp/hakusyo/kousei/26/dl/1-02.pdf#page=47)
- **経験や判断の共有が課題になる。** 厚労省が掲載した2026年3月の事業成果報告書は、日々の支援が職員の経験や個々の判断に頼り、仕事の進め方が属人化したり、見えにくくなったりしやすいと指摘している。[報告書・本文2ページ](https://www.mhlw.go.jp/content/12200000/001696968.pdf#page=4)
- **写真で工程を示す実践がある。** 厚労省の雇用上の配慮事例には知的障害のある人に対し、写真や大きな文字で作業工程を掲示し、いつでも確認できるようにする取組がある。[配慮事例・6ページ](https://www.mhlw.go.jp/file/05-Shingikai-11601000-Shokugyouanteikyoku-Soumuka/0000038290.pdf#page=6)

資料の確認日: 2026年11月5日。事業成果報告書は株式会社最中屋による「令和7年度 障害福祉分野の介護テクノロジー導入支援事業（民間団体実施分）」の報告書。

## 今回のMVPと、安全上の非交渉条件

- **MVP：** 1組織相当、タオルの包装という1作業、架空の本人プロフィール2件、担当者・本人・引き継ぎ先の3画面系統。本人の希望の登録、手本動画からの下書き、照合・承認、割当、ピクトグラム付きの本人操作、引き継ぎをつなぐ。支援記録からの改善は、作業中の支援・再開から切り離した次回向けの処理とする。
- **本人には承認済み版のみ提示。** Geminiの出力は常に候補・下書きとし、AIが人間の承認を代行しない。
- **承認済みの版は不変。** 更新時には新しい版を作り、実行中のセッションは開始時の版のままとする。
- **「手伝って」「やめる」を常時利用可能にする。** 「やめる」は確認待ちや通信状態に依存せず端末で即時停止し、失敗・競合時も停止を優先する。
- **個人の診断による自動最適化・作業速度での能力評価・本人への未承認手順の公開は実装しない。** デモ素材は架空データとチームで撮影した素材を用いる。
