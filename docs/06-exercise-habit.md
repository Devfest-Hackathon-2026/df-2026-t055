## 1. 元の案

- 生活習慣病や医療逼迫などの多方面の課題へのアプローチ
- 日々の生活習慣の見直しを行わせ、健康寿命を伸ばす。
- それぞれの年代にあった運動アプローチを行い長い人生を最後まで楽しくする。
- UIUXの工夫を行い、誰でもモチベーション高く続けられる工夫を行うべき

## 2. Why：誰の、どんな課題か

- カテゴリ候補: 医療・福祉
- 対象ユーザー候補（仮説、いずれか1層に絞る。未決定）:
  - デスクワーク中心の30〜40代: 残業や予定変更で「運動する時間」が毎日読めず、計画が崩れた日にやる気を失う。
  - 子育て世代: まとまった時間が取れず、隙間時間でできる小さな運動しか現実的でない。
  - 60代以降: 体力や既往への不安があり、「何を・どれだけやれば安全か」が分からず始められない。
- 継続を阻む理由の仮説（ヒアリングで検証する）:
  - 目標が高すぎる（最初から30分など）ため、できない日が出た時点で全体をやめてしまう。
  - 記録そのものが面倒で、記録が途切れると再開しづらい。
  - できなかった日に罪悪感を強める設計（ストリーク途絶の強調など）が離脱を招く。
  - 天気・体調・残業など外的要因で計画が崩れることへの「代替案」がない。
- 解決したい社会課題（仮説）: 運動習慣を続けにくいこと。生活習慣病や医療逼迫、健康寿命への影響は背景として扱い、短期間の開発で実証した効果としては扱わない。
- 根拠: 未確認。対象年代の運動習慣に関する公的統計（例：スポーツ庁「スポーツの実施状況等に関する世論調査」などを候補として）を確認し、対象者から「続かなかった場面と理由」を聞いて出典・日付とともに追記する。
- 人間が決める意図: 対象年代を1つに絞り、「無理なく続けられる行動」と「続けられなかった日をどう扱うか」の設計方針をチームで決める。健康効果の訴求範囲もここで線引きする。

## 3. What：解決策と最小の体験

- 解決の仕組み（仮説）: 「できなかった日」を失敗として扱わず、次の行動を小さくし直すリカバリー設計を中核にする。
  - 2段階目標: 「最低ライン」（例：ストレッチ1分、1駅分歩く）と「できたら上乗せ」を分ける。最低ラインの達成でも継続扱いにし、ハードルを常に届く範囲に保つ。
  - 見送りの正式化: 「今日は見送る」を正規の選択肢とし、理由（残業／天気／体調／気分など）をタップで記録する。理由に応じて翌日の目標を自動で軽くする。
  - 週次の振り返り: 実施・見送りのパターンを週1回見返し、自分の生活に合う曜日・時間帯・運動の種類を本人が調整する。
- 操作フロー案: 初回設定（年代・生活パターン・体力の自己申告）→ 今日の提案を確認 → 実施／見送り（理由タップ）を記録 → 週次で振り返る → 次週の目標を調整する。
- MVP候補:
  - 対象1層に絞ったオンボーディング
  - 2段階目標の提示と、実施・見送り・理由の記録（入力はタップ中心で10秒以内を目標）
  - 記録に応じた翌日目標の自動調整
  - 週次振り返り画面（実施パターンと、Geminiが生成する振り返りの問い）
- 今回の対象外候補: 全年代への対応、診断・治療の提案、ウェアラブル・ヘルスケア連携、健康寿命の改善効果の断定、競技・記録向上向け機能。
- 既存の手段との差（仮説）: 一般的な運動記録アプリは「実施した運動の記録・分析」、継続支援アプリは通知やストリークによる動機づけが中心で、「できなかった日の扱い」は弱い。本案は離脱の起点になる失敗日のリカバリーに絞る点が差になるかを検証する（比較対象：主要な習慣化・運動記録アプリを実際に触って確認する）。

## 5. AIをどこで、なぜ使うか

- プロダクト内の利用案: 週次振り返りでの記録要約と問い生成（例：「今週は残業の日に3回見送っています。目標を夜から朝に移しますか？」）。翌日の目標を軽くする判断材料の提示。
- その場面で使う理由: 継続の障壁は人ごとに違い、固定文の励ましでは届かない。個人の記録パターンを言語化する処理はAIが向く。一方、目標の数値調整や記録集計は固定ルールで足りる部分も多く、AIが要る範囲を切り分けて検証する。
- 人間が判断・確認すること: 対象者と提供範囲、運動内容の安全ライン（定型候補の選定）、目標変更の最終決定。AIに診断・治療・個人の体調への断定をさせない。体調不良の記録がある日は運動を促さない。
- 開発支援の利用実績: 文書整理の共通記録は[README](README.md#この文書でのai利用)を参照。以降は場面・使い方・理由・人間の判断を追記。

## 6. 検証・完成度・デモ

- 課題と効果の検証: 対象層の3〜5人に5日間使ってもらい、①記録を続けられた日数 ②1回あたりの入力時間 ③見送り理由の分布 ④振り返りの問いが翌日の行動を変えた場面、を確認する。結果は未検証で、長期の健康効果は別途検証が必要と明記する。
- UI・UXの確認: 対象年代の人が設定→記録→振り返りを一人で完了できるか、「見送る」が選びやすい（罪悪感を煽らない）文言・配置かを確認する。
- 安全性・データの扱い: 体調・健康情報は必要最小限にし、公開機能を持たない。無理な継続を促す表現を避ける。AI生成が失敗しても記録データは失われない設計にする。
- 拡張性・保守性: 対象層・記録項目を絞り、「記録・集計（固定ルール）」と「振り返り生成（AI）」を分離し、AIなしでも記録が成立する構成を検討する。
- デモ構成案: 続かない具体的な場面（残業で3日連続未実施）→ 2段階目標と見送り記録 → 翌日の目標が軽くなる → 週次振り返りで本人が目標を調整 → 短期検証の結果と限界（健康効果は未実証）を正直に示す。
