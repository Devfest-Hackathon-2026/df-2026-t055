# 追補案　今の工程でもういちど見る

[11/7の設計書](design-freeze-2026-11-07.md)の第2〜4節と第8節への変更案。本人が作業の途中で困ったときに、今の工程の補足を開き、試し直すか職員を呼ぶかを選べるようにする。MVPでは、タオルを袋に入れる工程で試す。撮影台本の6番にある、袋に引っ掛かったときの対処を使う。

## 本人画面

- 袋入れの写真と短文の下に「袋に 入らないとき」を表示する。押すと、同じ画面に「いったん 止めます。袋の 口を ひろげます。」を表示する。補足は初めは閉じておき、同じ操作で閉じられるようにする。
- 開閉しても工程番号は変わらない。「もどる」「つぎへ」「手伝って」「やめる」は補足を開いたまま使える。工程を移るか、職員の対応後に同じ工程へ戻るときは、補足を閉じた状態から始める。
- 開閉にはキーボードで操作できるコントロールを使い、読み上げでもラベルと開閉状態が分かるようにする。作業前に必ず知る必要がある注意は、既存の注意欄に表示する。

## 職員の編集・承認と配信

- 職員が手本と照合し、本人向けの補足のラベルと短文を編集する。既存の本人画面プレビューで開いた状態まで確認し、手順と一緒に承認する。
- 編集済みの工程と承認版の `learnerSteps` に、任意の `optionalHelp: { label, text }` を追加する。指定する場合は、ラベルと短文のどちらにも内容が必要。既存の本人用セッションAPIは、セッションが参照する承認版の補足だけを本人用レスポンスに含める。補足のない工程や既存の承認版では、開閉操作を表示しない。
- 補足の開閉は画面内で完結する。セッション状態、工程番号、支援要求を更新しない。

## 確認すること

- 補足を開閉しても同じ工程にとどまり、そのまま進む、戻る、職員を呼ぶ、やめる操作ができる。キーボードで開閉でき、読み上げで開閉状態が分かる。
- 補足のない工程には開閉操作が出ない。職員が下書きを変更したり、新版を割り当てたりしても、実行中のセッションで表示される補足は変わらない。
- 袋に引っ掛かった場面で、操作名を先に伝えず、本人が補足を見る、職員を呼ぶ、やめるのうち望む行動を選べるかを観察する。補足を開いた場合は、次に何をするか分かったかも確認する。チーム内の動作確認と、実際の利用者による確認の結果は分けて記録する。
