# 利用者の特性を登録し、写真のみの作業手順を選べるようにする

提案日：2026年11月7日。

対象は[設計フリーズ v0.1](design-freeze-2026-11-07.md)の利用者プロフィール、手順作成・承認、本人への表示、新人への引き継ぎ。本人に合う説明方法を初回登録時から記録し、文字を読むことに頼らず作業を確かめられる手順を用意する。

## 既存設計から変えること

既存設計は、架空の本人プロフィール2件を用意し、説明方法の好みを保存する。本人向けは写真と短文の組合せで、診断名は収集せず、Geminiにも送らない。

利用者を登録する職員向け画面を追加し、本人の希望、職員が確認した特性や説明方法、写真のみで表示するかを登録できるようにする。支援に必要で本人が共有を希望する障害に関する情報も、職員向けの任意項目として保存できる設計へ変更する。デモでは引き続き架空のプロフィールを使う。

## 初回登録と見直し

職員が本人と説明方法を確かめながら登録する。分からない項目は未確認のまま残せ、後から変更できるようにする。

| 登録する内容 | 保存する情報の例 | 使い方 |
| --- | --- | --- |
| 本人の表示名 | 事業所内で使う表示名 | 作業の割当と職員の確認に使う |
| 障害に関する情報（任意） | 本人や既存の支援資料から確認でき、支援で必要な内容 | 職員の支援・引き継ぎに使う。確認元と確認日を残す |
| 支援に関係する特性・希望 | 文字の読み取りや説明の受け取り方、一度に示す量、声かけや待つときの配慮 | 観察した事実、本人の希望、職員の提案を分けて記録する |
| 本人向けの表示方法 | 写真のみ／写真と短文 | 初回の手順作成と職員のプレビューへ引き継ぐ |
| 読み上げの希望 | 既存の音声あり／なし | 承認済みの読み上げを併用するか選ぶ |

表示方法は本人の希望と確認した使いやすさをもとに職員が選び、障害名から自動決定しない。登録時の設定を手順作成の初期値とし、作業ごとのプレビューで調整する。プロフィールを変更しても、承認済みの内容と実行中の表示は自動で切り替えない。

## 写真のみの手順を作って使う流れ

1. 職員が利用者を登録し、表示方法に「写真のみ」を選ぶ。
2. 職員が手本動画を登録し、その本人の手順を作る。Geminiには表示方法と、職員が確認した説明上の配慮を渡し、工程の区切りと写真候補の時刻を下書きさせる。
3. 写真は元動画から切り出す。押さえる手、動かす手、順番、途中の状態が見えるよう、職員が工程と写真を調整する。必要な動きが写っていなければ追加撮影し、意味が伝わる写真を用意する。
4. 職員が認証済みの画面で写真のみの表示をプレビューし、原動画と照合する。写真の差替えや工程の細分化で伝わりやすく整え、工程数は既存の上限20件の範囲で調整する。
5. 職員が提示する写真と順序、教え方を確認して承認し、本人へ割り当てる。
6. 本人には一度に1工程の承認済み写真を大きく表示し、工程の説明文と文字による注意書きは画面に表示しない。職員がマンツーマンで手本を示しながら写真の見方を伝え、必要な場面で説明する。本人が前後移動・支援要求・停止を選べる状態で作業を進める。

写真のみの設定は工程の説明表示に適用する。操作ボタンや支援待ち・停止の状態を絵で伝える設計は、[操作のピクトグラムの案（PR #9）](https://github.com/Devfest-Hackathon-2026/df-2026-t055/pull/9)として別に扱う。読み上げは本人の希望に合わせて併用できる。

写真と職員の説明で、本人に必要な注意点も伝えられることを承認前に確認する。文字の注意書きを非表示にする際は、その注意をどう伝えるかも確認し、職員の支援方法を引き継ぎに残す。

使って分かった分かりにくさは、職員がその場で支援して記録し、次回の手順を新しい下書きで改善する。本人に示す写真と手順は、職員が承認した内容を使う。

## 保存・生成・承認への接続

- `learners`には職員向けの障害・特性に関する記録と、表示方法の好みを追加する。利用者登録のAPIと画面を設け、登録・更新は所属の一致する職員に限定する。
- Geminiへは、明示した入力項目から表示方法と説明上の配慮だけを渡す。本人名、診断名、プロフィール全文は送らない。
- 生成開始時の表示方法と参照した配慮を下書きに保存する。承認版にも本人向けの表示方法を保存し、実行中のセッションは開始時の承認版を使い続ける。
- 写真のみでも、職員が照合する工程の短文、写真の代替テキスト、必要な注意、声かけ、完成基準は保持する。本人画面では写真を見せ、支援技術には写真の内容を伝えるテキストを提供する。職員画面と新人の引き継ぎ画面では、承認した説明と教え方を参照できる。
- 既存の確認・承認では写真の順序と本人への提示方法も確認する。短文の非表示によって、原動画照合や職員による承認を省略しない。
- 本人用の応答には障害名、特性の記録、職員メモを含めない。新人には、その作業の支援に必要で職員が承認した教え方を渡す。

写真の代替テキストを保つ方針は[W3CのNon-text Contentの解説](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html)を参考にする。

## 確認すること

- 初回登録から、写真のみの下書き・プレビュー・承認・割当・本人表示・新人の参照まで一連で確認する。
- 本人が写真と職員の説明で手順を確かめられるか、写真や説明のどこを直すと使いやすいかを確認する。
- 写真と短文、写真のみ、必要に応じた読み上げの使い方を本人と確かめ、設定を見直せることを確認する。
- 注意点の伝達、工程数上限、写真不足、プロフィール未確認、プロフィール更新後も作業中の表示が変わらないことを確認する。
- 障害・特性の記録の閲覧権限、Geminiへの送信項目、本人用応答への混入がないことを確認する。
