# 場所や担当が変わっても使える支援パスポート

- 投稿: 壁打ちで具体化した案
- 状態: 保留・未検証

## 1. 元の案

通所先の変更、短期入所、入院などで担当が変わるとき、本人の伝え方・好み・必要な配慮を引き継ぎ、何度も一から説明する負担を減らす。

## 2. Why：誰の、どんな課題か

- カテゴリ候補: 医療・福祉。
- 対象・課題の仮説: 初めての相手に本人に合う関わり方を伝える本人・家族・支援者。
- 根拠: [NHSの支援パスポート](https://www.nhs.uk/conditions/learning-disabilities/going-into-hospital/)に同種の情報共有の実践がある。対象現場での不足は未確認。
- 意図: 本人に関する情報を必要な相手・場面へ引き継ぐ。

## 3. What：解決策と最小の体験

- 操作案: 既存情報を整理→本人・支援者が内容と共有先を確認→受け入れ先が必要な項目を見る→更新する。
- MVP候補: 1つの引き継ぎ場面、少数の確認済み項目、共有範囲と確認日。
- 対象外: 全機関の記録連携、本人像の自動確定、古い情報の無条件な再利用。

## 4. How：Google技術と候補比較

- 候補: Geminiで資料の整理・場面別の下書き、Cloud Runで実行。保存と共有制御は要設計。未採用・未実装。
- メリットの仮説: 既存資料から必要な項目を抽出できる。
- デメリット: 必要な情報の抜け、古い解釈の固定、共有・更新管理。
- 比較対象: 紙の支援パスポート、既存の引き継ぎ、[Volition](https://www.myvolition.org/)、汎用AIによる資料整理。

## 5. AIをどこで、なぜ使うか

資料整理の下書きに使う案。本人が何を好むかをAIが確定せず、情報源と確認日を残す。文書整理・調査でのAI利用は[共通記録](intellectual-disability-welfare-review.md#ai利用と判断)を参照。

## 6. 検証・完成度・デモ

送り手の準備と受け手の確認の両方を含め、既存の引き継ぎと比較する。個人情報を扱う共有範囲、取り下げ、更新責任が必要。架空資料での表示確認は本人の安心や支援効果の実証ではない。

## 7. 未決定事項・次の確認・学び

### 選定しなかった理由

- 支援パスポート自体は既存の取り組み。
- 施設をまたぐ共有・更新は、アプリを作るだけでは運用が決まらない。
- 作成・最新化の負担が、紙や既存の連絡を上回るか未確認。
- 必要な相手が実際に読む・使うかを検証できていない。

再検討条件: 一つの引き継ぎ場面で、情報の何が伝わらず困ったか、送り手・受け手の双方を確認できること。開発による学びは未記入。
